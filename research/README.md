# GS2500 전국 점포 기초조사

조사일: 2026-09-21 (KST). 대상: **대한민국 GS25 편의점**. GS THE FRESH, 주유소, 해외 GS25는 별도 모집단이다.

## 목적과 진행 상태

임의의 3D 매장을 늘리는 작업보다 **전국 점포 모집단 → 상권/서비스 분류 → 대표 점포의 실제 공간 조사 → 시뮬레이션 검증**을 먼저 수행한다.

현재 데모의 매장 9종·고객·상품·행사 효과는 합성이다. 이 조사로 검증된 실제 전국 점포의 내부 구조나 고객 행동이라고 해석하지 않는다. 공개 상가 목록에서 브랜드를 추출한 결과도 GS25 본사의 공식 전점 명부와 동일하다고 보장하지 않는다.

- 전국 상가 원본: 소상공인시장진흥공단 2026-06-30 스냅샷, 2026-08-05 게시. 무료 CSV, 분기 갱신, 페이지상 이용허락범위 제한 없음. [원본 페이지](https://www.data.go.kr/data/15083033/fileData.do)
- 공식 매장검색: 새 GS리테일 홈페이지에서 삼성역점의 점포명·주소·서비스를 직접 확인했다. 점포별 검증에 활용하되, 공개 조회 기능을 대량 수집 허가나 전체 목록 API라고 간주하지 않는다. [공식 GS25 / 매장 찾기](https://www.gsretail.com/brand/gs25)
- 공개 상가 원본으로 확인되지 않는 POS·재고·점포 도면·실제 방문자 프로필은 미확인 상태로 남긴다.
- 내려받은 원본 `소상공인시장진흥공단_상가(상권)정보_20260630.zip`은 조사자의 로컬 다운로드 폴더에 보존한다. 파생 점포 데이터는 `data/`에 저장하고 Git/웹 배포에서 제외한다. 원본 SHA-256·분석 스크립트·조사 방법을 함께 남긴다.

**[전국 1차 추출 결과](NATIONWIDE_FINDINGS.md): 원본 2,772,484행 → GS25 후보 15,630건 (일치 14,717 / 재검토 913). 공식 전점 수는 아니다.**

자료 목록은 [DATA_SOURCES.md](DATA_SOURCES.md), 실제 공간 차별화 사례는 [STORE_FORMAT_EVIDENCE.md](STORE_FORMAT_EVIDENCE.md), 추출·검증 실행법은 [scripts/README.md](scripts/README.md)를 참조한다.

## 전국 마스터를 만드는 규칙

1. 동일 스냅샷의 모든 지역 CSV를 읽고 파일별 행 수·헤더·SHA-256을 기록한다. 다운로드 누락 지역이 있으면 전국 완료로 표시하지 않는다.
2. 유니코드·대소문자·띄어쓰기 정규화 후 `GS25`, `지에스25`, `지에스이십오` 등 브랜드 후보를 찾는다. 원문 상호와 업종은 보존한다.
3. 편의점 업종 일치 여부와 브랜드 불명확 여부를 분리한다. 비편의점 업종으로 등록된 GS25 후보는 검토 대기이며 무조건 제거하지 않는다.
4. 상가업소번호를 소스 내부 ID로 보존한다. 과거 분류체계/ID 개편이 있어 장기간 동일 점포 ID라고 가정하지 않는다. [공공 API의 변경 이력 안내](https://www.data.go.kr/dataset/15012005/openapi.do?lang=ko)
5. 같은 건물의 다른 층/호/점포를 주소만으로 합치지 않는다. 이름·주소·거리 중복은 검토 플래그로 남긴다.
6. 공식 점포검색과 표본 대조해 오탐·미탐을 측정한다. 최종 전점 커버리지 확인에는 GS 본사의 기준일이 있는 점포 마스터가 필요하다.
7. 좌표 유효성, 지역 누락, 업종 불일치, 주소 중복, 기준일을 결과에 함께 공개한다. 확신할 수 없는 값은 `null`/미확인이다.

## 공간 유형은 색상보다 기능으로 분류

지역 색상은 표현 장치일 뿐 행동 변수로 쓰지 않는다. 한강변이라고 모든 매장에 동일한 수요 배수를 주지 않는다.

- 상권 축: 오피스, 역세권/환승, 주거, 대학, 관광, 공원/수변, 산업/물류, 농어촌, 병원/캠퍼스 등 특수시설. 중복 분류를 허용한다.
- 공간 축: 영업면적, 가로세로 비, 출입구 수/위치, 통로 폭, 곤돌라 수·길이, 계산대 수, 냉장벽 길이, 좌석 수, 창고/피킹 공간. **실측 전 수치는 가정**이다.
- 서비스 축: CAFE25, 조리식품, 셀프조리, 택배 접수/수령, ATM, 신선강화, 주류특화 등 공식 검색의 관측값을 사용한다.
- 운영 축: 영업시간, 입고/보충 시간, 인력, 폐기/품절, 배달·픽업 동선. 전 점포 24시간 영업이라고 하드코딩하지 않는다.

전국 분포를 확보한 후 `지역 × 상권 × 공간 규모 × 서비스`로 층화 표본을 구성한다. 초기 현장 검증 규모로 24~36개 점포를 제안하지만, 이는 **설계 제안**이며 통계적으로 전국 대표성이 입증된 표본이 아니다. 실제 전국 비중·희소 유형·데이터 접근성을 보고 확정한다.

## 실제 공간 조사 체크리스트

- 점주/관리자 허가를 받은 도면 또는 얼굴·결제 화면을 제외한 현장 촬영.
- 매대 ID, 실제 좌표/방향, 폭·높이·깊이, 층 높이, 접근 가능한 면, 통로와 시야 차폐.
- SKU별 정확한 좌표, 페이싱 수, 가격표·행사물, 좌우/상하 이웃, 포장 크기, 진열/보충 재고.
- 냉장 필요 상품은 냉장 설비에만 배치. 데모의 모든 SKU를 행사대에 놓는 단순화는 실제 배치 제약으로 교체해야 한다.
- 2·3층의 효과는 고정 정답이 아니다. 사람의 눈높이, 매대 규격, 통행 방향, 상품 크기/브랜드/할인과 함께 검증한다.
- 사람을 추적하는 식별정보 없이 시간 구간별 입장·체류·대기·구매/비구매 집계부터 수집한다.

## 행사·트렌드 기록 형식

`event_id, title, source_url, published_at, event_start/end, area_geometry, affected_store_ids, evidence_kind, metric, baseline_period, sample_size, uncertainty, assumptions`

‘축제가 열림’, ‘해당 상권에 인파가 늘었다는 관측’, ‘특정 점포 매출이 증가했다는 보도’, ‘시뮬레이터가 부여한 수요 배수’를 별도 필드로 둔다. 공식 일정만 있다고 인파/매출 효과가 관측된 것은 아니다. 배수는 기본적으로 미정이며, POS 검증 전 가정을 실제 효과로 승격하지 않는다.

같은 요일·시간대, 날씨·행사·가격·재고·영업시간을 정렬하고 영향권 밖 비교 점포를 포함한다. 이벤트 당일 매출이 높아도 진열 개선의 성과라고 단정하지 않는다. 결품 시 판매량은 잠재 수요보다 낮을 수 있다.

## JEV 연결 정정

Vercel Gateway 키는 모델명이 아니다. 이번 프로젝트의 의사결정 모델은 **`typesafe-ai/jev`**이며 GPT로 자동 대체하지 않는다.

- 공식 경로: `POST https://ai-gateway.vercel.sh/v1/evaluate`
- 입력: `model`, `state`, `questions`.
- `state`에 근거와 기준일이 붙은 점포·방문 목적·관찰 가능한 SKU·정확한 배치·이웃·재고·가격·행사 정보를 넣는다.
- `questions`에 현재 가능한 행동과 `skip`/근거 부족 선택지를 한정한다. 확률과 confidence를 실제 매출 확률이나 관측 구매율로 취급하지 않는다.
- JEV는 자유서술 설명을 만드는 모델이 아니다. 화면 설명은 입력의 근거와 선택 결과를 연결한 템플릿으로 구성한다.
- 실제 재고, 예산, 충돌, 계산 및 동시성 검증은 월드 엔진의 책임이다. 응답이 늦으면 가상 시계의 해당 판단을 기다리게 하거나 명시적으로 기록한 로컬 fallback을 쓴다. GPT fallback은 사용하지 않는다.
- 이번 조사 단계에는 키를 파일/브라우저/저장소에 추가하거나 모델을 실호출하지 않았다.

출처: [Vercel JEV 모델](https://vercel.com/ai-gateway/models/jev), [Evaluation HTTP API](https://vercel.com/docs/ai-gateway/modalities/evaluation#http-api), [JEV의 입력과 한계](https://vercel.com/i/what-is-jev).
