# GS2500 점포 실행 실험실

GS25 영업관리 매니저가 담당 점포의 합성 전년 동기비를 보고 개입할 곳을 고른 뒤, 같은 조건의 24시간 3D 실험을 비교하고 점주가 실행할 수 있는 작은 변경만 승인하는 데스크톱 웹앱입니다.

- 공개 앱: [https://gs2500.vercel.app/](https://gs2500.vercel.app/)
- 제출물 허브: [https://gs2500.vercel.app/deliverables/](https://gs2500.vercel.app/deliverables/)
- 공개 GitHub: [https://github.com/jin-ttao/gs2500](https://github.com/jin-ttao/gs2500)

모든 점포, 매출, 재고, 제안, 사진, 4주 관찰은 합성 데모 데이터입니다. 실제 GS25 데이터, 계정, POS, 문자, 발주, 사내 시스템, 실시간 SNS와 연결하지 않습니다. 시뮬레이션 결과는 실제 고객 행동 예측이나 인과적으로 입증된 매출 상승이 아닙니다.

## 3분 발표 경로

1. **성과와 개입**: 담당 9개 합성 점포의 전년 동기비를 보고 삼성역점 `H-0412`를 고릅니다.
2. **현재 매대와 근거**: 별도 합성 현재 기준선 `samsung-b03-current-v1`, B-03 매대, 재고와 작성된 합성 관찰을 확인합니다.
3. **24시간 비교**: 각 점포의 A/B/C/D 실제 엔진 결과 36개를 봅니다. 같은 점포의 네 후보는 같은 시드, 초기 총재고, 잠재 고객 일정을 사용합니다.
4. **3D 행동**: 삼성역점 후보 B의 완료된 24시간 기록을 최대 12명의 실제 기록 경로로 24초에 재생합니다.
5. **매니저 승인**: 후보 B 전체 결과를 참고해 제로 스파클링과 담백 크래커만 옮기는 12분 안을 승인하고, 실제 발송되지 않는 안내 문자 초안을 수정합니다.
6. **점주 실행**: 승인한 점포, B-03 매대, 후보 B만 봅니다. 현재 사진 위 위치 표시와 선반 이동 도식을 읽고 수용, 부분 실행, 거절 중 하나를 고릅니다.
7. **4주 회고**: 제안, 승인, 회신, 사진의 분모를 분리하고 좋은 관찰, 부진, 미회신, 미승인 사례와 다른 설명 가능성을 함께 봅니다.

발표용 영상은 위 경로를 5장으로 요약한 무음 자막형 영상입니다. 한국어 발표 스크립트를 함께 제공합니다. 실제 길이는 `deliverables/index.html`과 아래 검증 기록에 적습니다. 앱의 클릭 전환은 오래 걸리는 계산을 기다리지 않도록 검증된 완료 기록을 사전 재생합니다.

## 데이터 진실성

### 서로 다른 세 시점

| 화면 | 의미 | 출처 |
| --- | --- | --- |
| 전년 동기비 | 점포 개입 우선순위를 위한 작성된 합성 실적 | `app/scenario.js` |
| A/B/C/D | 로컬 규칙 엔진이 계산한 24시간 합성 실험 | `app/data/experiment-results.json` |
| 4주 회고 | 실행 뒤 판단을 연습하는 별도 합성 관찰 | `app/scenario.js` |

30일 시뮬레이션은 없습니다. 4주 회고 숫자는 24시간 결과를 늘린 값이나 전망이 아닙니다.

### 현재 진열과 후보 A

`CURRENT_BASELINE`은 점주 안내를 위해 별도로 작성한 현재 합성 fixture이며 엔진 후보가 아닙니다. 후보 A는 본사 표준안이라는 비교 후보입니다. A를 현재 진열이라고 부르지 않고 현재 대비 매출 상승률도 계산하지 않습니다.

삼성역점의 실제 24시간 결과는 다음과 같습니다.

| 후보 | 역할 | 모의 결제매출 | 구매자 | 결품 수요 |
| --- | --- | ---: | ---: | ---: |
| A | 본사 표준안 후보 | 1,646,300원 | 470명 | 328건 |
| B | 재고 우선안 | 1,857,300원 | 500명 | 232건 |
| C | 균형 후보안 | 1,621,500원 | 458명 | 365건 |
| D | 신상품 탐색안 | 1,524,400원 | 439명 | 387건 |

이 실행에서는 B의 절대 매출이 가장 높습니다. 앱은 각 점포의 동률과 역효과도 계산 결과 그대로 표시합니다. 점포 간 절대 매출은 상권, 시드, 재고 배율이 달라 직접 순위로 쓰지 않습니다.

### 작은 변경안

승인 ID는 `P-SAM-B03-B-01`입니다. 후보 B 전체 배치의 결과를 참고하되, 점주에게는 아래 두 이동만 제안합니다.

- 제로 스파클링: 1단 2열에서 3단 2열
- 담백 크래커: 3단 2열에서 2단 4열

예상 작업은 12분이고 신규 발주는 없습니다. 이 두 상품만 옮긴 효과는 별도로 시뮬레이션하지 않았다고 화면에 표시합니다.

### 합성 페르소나와 엔진

NVIDIA `Nemotron-Personas-Korea` 합성 원본 1,000개를 사용합니다. 실제 GS 고객이나 모집단 대표 표본이 아닙니다. 출처, 라이선스, 추출, 파생 가정은 [`demo/data/PERSONA-SOURCE.md`](demo/data/PERSONA-SOURCE.md)에 있습니다.

정적 공개 경로는 `local-rule` 엔진의 완료 결과와 `day-replay/1` 기록을 사용합니다. API 키가 필요하지 않습니다. `demo/server.mjs`와 선택적 JEV 호출은 로컬 Node 서버에서만 쓰며 Vercel 정적 결과물에 포함하지 않습니다. 모델 실호출을 했다고 표시하지 않습니다.

## 승인, 점주 회신, 사진 보존 범위

승인과 점주 회신 메타데이터는 같은 브라우저의 `localStorage`에 저장됩니다. 이는 인증, 접근 제어, 기기 간 전달, 서버 영구 저장이 아닙니다.

- 승인 전에는 점주 화면에 제안이 보이지 않습니다.
- 승인 뒤에는 승인 스냅샷의 점포, 매대, 후보, 상품 이동만 보입니다.
- 점주는 화면에서 진열을 편집하지 않고 실제 현장에서 수용, 부분 실행, 거절을 고릅니다.
- 사진은 JPG, PNG, WebP와 최대 10MB만 선택합니다.
- 선택한 사진 파일은 브라우저 탭의 로컬 미리보기에만 존재하며 서버로 업로드하지 않습니다.
- 새로고침 뒤에는 이미지 바이트와 미리보기가 사라집니다. 파일명, 형식, 크기, 선택 시각, 접수 상태만 같은 브라우저에 남습니다.
- 사진 내용을 자동 판독하거나 진열 완료를 검증하지 않습니다.
- `발표용 합성 변경 사진 불러오기`는 번들에 포함된 합성 이미지로 같은 접수 경로를 보여줍니다.

## 실행과 빌드

필요 환경은 Node.js 22 이상과 npm입니다.

```bash
npm install
npm test
npm run build
npm run preview
```

`http://127.0.0.1:4173/`을 엽니다. `npm run build`는 다음을 수행합니다.

1. 기존 `demo/`를 기존 빌드 스크립트로 빌드합니다.
2. 루트 앱, 사전 계산 데이터, 기존 3D 모듈, 제출물을 `dist/`에 복사합니다.
3. `server.mjs`, `.env`, `.env.*`가 정적 결과물에 없음을 검사합니다.

사전 계산 결과를 다시 만들려면 다음을 실행합니다.

```bash
node scripts/generate-experiment-fixture.mjs
```

이 작업은 9개 점포와 A/B/C/D 36개 세계를 실제 로컬 규칙 엔진으로 24시간 끝까지 계산합니다. 삼성역점 B의 `day-replay/1` 기록도 함께 만듭니다.

발표 자료와 영상은 번들 Python, `say`, `ffmpeg`로 생성합니다.

```bash
/Users/jintae/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 scripts/build-submission.py
```

## 검증 기록

2026-09-22 KST에 다음을 확인했습니다.

- 자동 테스트: 루트 11개 + 기존 `demo/` 162개 = **173개 통과**
- 정적 빌드: 성공. `server.mjs`와 `.env*` 제외 확인
- 로컬 브라우저: 승인 전 비노출, 승인 뒤 정확한 삼성역점 B-03 후보 B 전달
- 로컬 브라우저: 부분 실행과 거절 회신, 사진 접수, 새로고침 뒤 미리보기 소멸과 메타데이터 보존
- 파일 실패: JPG/PNG/WebP 외 형식과 10MB 초과를 데이터 계약 테스트에서 거절
- 로컬 브라우저: 3D 연결 실패 때 수치와 승인 경로 유지, 재시도 제공
- 로컬 브라우저: 4주 회고의 제안 4, 승인 3, 회신, 사진 분모와 점주 선택 연결
- 브라우저 콘솔: 검증 경로에서 오류와 경고 없음
- 공개 URL: 승인 전 비노출, 3D 기록 연결, 승인 뒤 정확한 전달, 부분 실행, 사진 접수, 새로고침, 4주 회고를 production에서 다시 확인
- 공개 URL: 강제 3D 연결 실패에서도 24시간 수치와 승인 경로 유지
- 공개 제출물: 앱, 5장 PDF/PPTX, 1분 30초 영상, `/goal` 원문, 메인 세션 JSONL 응답 200 확인
- 공개 비노출: `demo/server.mjs`와 `demo/.env.local` 응답 404 확인
- 발표 경로 자동 클릭 측정: **4.8초**. 읽기와 설명 시간을 제외한 순수 화면 전환 시간
- 무음 자막형 데모 영상: **1분 30.0초**, 1280×720 H.264/AAC

샌드박스 기본 실행에서는 localhost 포트 제한으로 기존 서버 테스트 11개가 열리지 않았습니다. 같은 테스트를 localhost 권한이 있는 검증 환경에서 다시 실행해 162개 전체 통과를 확인했습니다. 제품 결함에 의한 실패가 아닙니다.

## 알려진 한계

- 합성 점포 9개와 후보 4개는 현재 데모 설정이며 제품의 고정 한계가 아닙니다.
- 실제 계정, 점포 시스템, POS, 재고, 문자, 발주, 사진 저장, 이미지 판독은 구현하지 않았습니다.
- 같은 브라우저의 데모 상태는 실제 접근 제어나 점주 전달이 아닙니다.
- 3D 고객 행동은 제한된 합성 정책 결과이며 실제 고객 행동 예측이 아닙니다.
- 4주 사례는 합성 회고이며 실험의 인과효과를 증명하지 않습니다.
- 사진 파일 선택 실패는 브라우저 자동화 환경의 로컬 파일 접근 제한 때문에 UI 자동화 대신 순수 데이터 계약 테스트로 검증했습니다. 실제 UI에서 같은 검증 함수를 사용합니다.
