# 행동·동선·구매 반사실 검증

검사일: 2026-09-22, KST. 대상: 로컬 규칙 엔진 `local-rule/3`.

## 결론

3개 합성 점포 × 4개 후보의 24시간 운영을 실제 엔진으로 끝까지 실행했다. 점포별 동일한 원본 합성 페르소나 1,000명·예정 방문 기회·시드를 네 후보에 적용했다. 후보 변경이 **실제 결제 상품, 방문한 매대의 순서, 선택한 매대 접근 좌표**에 반영되는 것을 확인했다. 결제·예산·재고 보존 검사는 모두 통과했다.

이 결과는 코드의 내부 일관성과 입력 변화에 대한 반응을 검증한 것이다. 한국 소비자 행동을 정확히 재현한다거나 실제 GS 매출을 예측한다는 검증은 아니다. 이번 검사는 외부 API를 호출하지 않았으며 JEV의 판단 정확도를 평가하지 않았다.

## 재현

`demo` 폴더에서 다음 명령을 실행한다.

```sh
node --test behavior.test.js behavior-world.test.js
node scripts/audit-behavior.mjs
```

감사 스크립트는 실행별 집계와 최종 비교 결과를 JSON으로 표준 출력한다. 실제 데이터 연결·발주·결제·외부 모델 호출은 없다. 12개 세계의 이번 측정 시간은 **37.792초**였다. 이는 이 컴퓨터의 Node 실행 측정이며 브라우저 처리 속도를 보장하지 않는다. 개인별 시간대 가중치 적용과 기술용 인물 분류 번호의 효용 영향 제거 후 다시 측정한 결과다.

입력은 `data/nemotron-korea-sample.json`의 원본 행을 `loadPersonaCatalog`로 불러와 출처 검증과 변환을 거친다. 출처는 [NVIDIA Nemotron-Personas-Korea](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea), 리비전 `ada0f5b53a38bb5a30cce09358adde883c1ab63a`, CC BY 4.0이다. 실존 고객이나 모집단 대표 표본이 아니라 공개 **합성** 인물 1,000명의 부분집합이다.

서로 다른 대상의 SHA-256을 구분한다. 파일 바이트 전체와 레코드 배열의 직렬화 결과는 동일한 입력이 아니므로 아래 두 값이 다른 것이 정상이다. 감사 스크립트는 둘 다 출력하며 두 번째 값이 매니페스트와 일치하는지 검사한다.

- 파일 바이트 전체: `fca0a7ff3a29c7023c280d685650a8207c7c06f3184e15d7448ee6333f35f37c`
- `JSON.stringify(payload.records)`의 UTF-8 바이트: `119f09e515419b933bef808405e805b13f376b972895f736c8fdf41cbedd6976` — 매니페스트 `integrity.canonicalRecordsSha256`과 일치

## 확인한 경계 조건

단위 검사 10개와 세계·방문 기회 회귀 검사 5개, 총 15개가 통과했다.

- `생수만 구매`는 물 이외의 상품을 선택할 수 없는 제약으로 적용된다. 다른 상품의 선호도나 긍정적 기억으로 이를 덮어쓰지 않는다.
- `신상품 기피`와 구조화된 상품 회피 기억이 구매 후보를 제한한다. 단순히 ‘재고 없음’이라는 기록을 영구적인 기피로 추정하지 않는다.
- 예산 7,000원에서 1,600원 상품을 6,900원으로 바꾸면, 둘 다 구매 가능하더라도 가격 효용이 달라져 선택 점수가 0.25 이상 낮아진다.
- 예산이 상품 가격과 정확히 같으면 구매 가능한 상태다. 예산 1,600원·생수만 구매하는 12명의 실제 방문에서는 매대 이동·상품 관찰·생수 결제가 발생했다. 기존의 고정 1,700원 종료 기준 때문에 바로 퇴장하지 않는다.
- 같은 물 구매 목적에 회피 기억을 추가한 실제 12명 방문에서는 결제가 발생하지 않았다.
- 00:49의 합성 대학생 방문은 ‘심야’ 방문 기회로 표시한다. 원본의 낮 수업 이력은 보존하지만, 이를 지금 수업 사이에 방문 중이라는 사실로 만들지 않는다. 별도로 지정한 물 구매 목적은 유지한다.
- 원본 페르소나의 기술용 `archetypeIndex`만 바꾸어도 입장 확률·예정 시각·결제·목적지 결과가 바뀌지 않는다. 다섯 화면용 분류 번호를 구매 성향으로 사용하지 않는다.
- 개인의 가정된 `schedule.hourlyWeights`를 바꾸면 같은 인물 UUID 집합의 방문 기회 시각이 실제로 달라진다. 이 가중치는 생활 기록의 실측치가 아니라 공개 이야기와 데모 가정을 바탕으로 설정한 입력이다.
- 화면에 보이는 위치와 판단에 쓰는 위치는 같은 배치 함수를 사용한다. 행사 매대뿐 아니라 일반 진열대·냉장고의 SKU 위치도 후보별로 달라진다.
- 진열 재고가 0이면 `pick`을 허용하지 않고 미충족 수요 기록만 허용한다. 예산·목적에 맞는 상품을 살펴보러 갔다가 품절을 확인할 수 있으므로, 방문 전에 모든 재고를 아는 에이전트로 취급하지 않는다.

`deriveBehavior`는 구조화된 제약과 소수의 명시적 문구만 처리한다. 인식하지 못한 문장을 해석했다고 주장하지 않는다. 전체 원문 이야기는 별도 입력에 보존되며, 지역·직업·나이만으로 임의의 구매 목적이나 실제 생활 일정을 확정하지 않는다.

## 보존·안전 검사

- 결제 5,432건: 실제 입장한 사람만 결제, 방문당 중복 결제 없음, SKU 가격 합계와 결제액 일치, 개인 예산 초과 없음.
- 결제 상품 9,506개: 명시적 상품·신상품·기억 제약과 바스켓 한도 확인.
- SKU 재고 항등식 288건: `초기 보유량 = 마감 진열 + 마감 창고 + 결제 수량`. 음수 재고 및 매대 용량 초과 없음.
- 모든 이벤트의 시각이 00:00–24:00 범위 안에 있고, 마감 후 남아 있는 미결제 고객 없음.
- 점포별 A/B/C/D의 예정 시각·인물 UUID·입장 난수는 정확히 일치.
- 외부 모델 호출 0건. 기록된 지표는 로컬 계산의 결과이고 실제 매출이 아님.

이전 엔진이나 다섯 고정 페르소나로 얻은 매출·구매자 수와 이번 수치가 달라지는 것은 의도된 변경이다. 구매 목적·가격·기억·SKU별 접근 지점을 실제 판단에 반영하고 원본 합성 인물 집단을 바꾸었으므로, 과거 매출 숫자를 정답으로 고정한 테스트는 적절하지 않다. 재현 시에는 같은 엔진·원본 파일·시드·정책 설정을 함께 사용해야 한다.

## 남은 한계

실제 매장 POS·재고·방문 기록에 대한 보정이나 예측 정확도 평가는 하지 않았다. 가격 민감도·예산·방문 시각·품목 효용은 작성한 가정이다. 복잡한 식이 제한과 긴 이야기의 의미를 완전히 이해하는 모델도 아니다. JEV 실호출을 붙이더라도 이런 정확도가 자동으로 검증되는 것은 아니며, 이 감사 결과를 AI 성능 점수나 실제 사업 매출 개선 증거로 사용하면 안 된다.
