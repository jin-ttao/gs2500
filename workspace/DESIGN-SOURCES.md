# 운영 워크스페이스 디자인과 출처

2026-09-22 사용자의 우선순위 변경: 유료 JEV 연결을 보류하고 운영 UX/UI를 먼저 완성한다. 로컬호스트만 사용한다.

## 확인한 레퍼런스

- **현재 적용: [팀 Obolus](https://github.com/DanRo-AX/Obolus-GoogleCloudAI-Solana).** 사용자가 팀 소유이며 재사용 가능하다고 확인했다. 실제 AppLayout/AppSidebar, Memory, Dashboard, Archive/Transactions, button/primitives의 구조·스타일을 기존 GS DOM 렌더러로 포팅했다. `cardGradient.ts` 로직은 타입만 제거해 재사용했고 원본 Inter/WantedSans/GeistMono 폰트와 공식 OFL 고지를 동봉했다. 자세한 원본 커밋과 파일 매핑은 [OBOLUS-PORT.md](OBOLUS-PORT.md). 공개 저장소라는 사실만으로 일반 재사용 라이선스가 있다고 주장하지 않는다.
- [Grok Bot reconstructed](https://github.com/b-nnett/grok-bot-0.18-reconstructed): `frontend/`와 `docs/assets/router-settings.png`를 읽기 전용 확인. 네이티브 앱의 차콜 패널, 작은 사이드바, 절제된 구분선, 부드러운 카드 계층을 참고했다. 저장소 `NOTICE.md`는 원본 코드의 재배포 라이선스를 부여하지 않는다고 명시한다. 따라서 코드·아이콘 폰트·로고·바이너리·이미지를 프로젝트에 복사하지 않았다. `studio.css`와 UI 구현은 새로 작성했으며 Grok 공식 컴포넌트의 사용을 주장하지 않는다.
- [21st.dev Area Chart / REAVIZ](https://21st.dev/@reaviz/components/area-chart-1): 사용자가 열어둔 Chrome 탭에서 카드 안의 범례·영역 차트·지표 행과 공개 컴포넌트 코드를 확인했다. 현재 앱은 React가 아니므로 레퍼런스의 React/Reaviz/Framer Motion 소스를 통째로 설치하지 않고 SVG 차트·접근성 데이터 표를 직접 구현했다.
- [21st.dev Course Design Cards](https://21st.dev/@kristen17/components/course-design-cards): 제목·날짜·진행 상태·메타데이터를 구분하는 카드 계층을 참고했다.
- [21st.dev Incident Status Timeline](https://21st.dev/@cnippet-dev/components/incident-status-timeline): 날짜·상태·설명으로 이어지는 기록 목록을 참고했다.

Grok/21st.dev는 이전 시안의 디자인 참고였고 코드·샘플 수치를 복사하지 않았다. 현재는 사용자 허락을 받은 Obolus 포트가 우선한다. 시각 체계는 `obolus.css`, 운영 화면은 `operations-view.js`, 색상/텍스처는 `obolus-surfaces.js`다. 기존 `studio.css`는 보존하지만 더 이상 로드하지 않는다. GS 차트·도메인 로직은 기존 구현이며, Obolus의 결제·지갑·인증·외부 API는 가져오지 않았다.

## 운영 루프의 제품 설계

1. **현장 확인:** 사진은 증거 원본으로 접수하고 사람이 상품·단·열·운영 이슈를 확인한다. 현재 자동 이미지 판독은 없다.
2. **맥락 연결:** 품절·행사·날씨·트렌드·진열 변경을 일자별 매출과 나란히 놓는다. 같은 날 발생했어도 원인이라고 단정하지 않는다.
3. **작은 실행 제안:** 품절은 창고 확인·보충부터, 진열은 실제 슬롯의 작은 비교부터 제안한다. 상품·위치·근거·교란요인·다음 측정값을 함께 보여준다.
4. **사람의 승인:** 기존 시뮬레이션 후보 비교 → 관리자 승인 → 점주 수용·부분 실행·거절을 유지한다. 새 운영 추천은 해당 후보와 동일한 계산이라고 주장하지 않으며 매출 상승률을 만들어 붙이지 않는다.
5. **다음 관찰:** 전·후 상품 매출과 동일 기간, 사진, 작업 여건을 다시 기록한다. 기록이 추가되면 점포별 근거·위치 가설·우선순위가 규칙에 따라 갱신된다. 관찰 부족/반복 관찰/혼재는 근거 상태이며 통계적 신뢰도나 모델 학습 완료가 아니다.

## 현재 데이터 경계

- 홈 차트: 작성된 28일 **합성 점포 전체 일매출**, 7/14/28일 필터. 비교 기간 데이터가 부족하면 비교 상승률을 표시하지 않는다.
- 사용자 전후 금액: 사람이 입력한 상품/범위의 금액. 차트의 전체 점포 합계와 섞지 않는다.
- 3D·후보 예상: 기존 24 SKU의 30일 로컬 모형 계산. 위 관측 예시와 별도다.
- 사진·관찰·승인: 현재 탭의 메모리에서만 보존. 새로고침하면 초기화. 사진을 외부 서버나 모델로 전송하지 않는다.
- JEV: 보류. 준비된 어댑터는 HTTP 서버나 UI에 연결하지 않는다.

## 실제 서비스 확장 시 필요한 조건

사진에서 SKU/좌표를 추출하는 모델에는 사람의 정정 화면과 원본-정정 이력이 필요하다. POS·가격·행사·품절·보충 시점을 같은 SKU 및 시간 기준으로 연결하고, 위치 후보는 재고와 작업 제약을 만족해야 한다. 효과 추정은 비슷한 요일·시간대와 대조 조건을 비교해야 하며 불확실성을 보여줘야 한다. 장기 기록·모델 학습·실제 매출 최적화는 현재 로컬 데모 범위 밖이고 아직 구현됐다고 주장하지 않는다.
