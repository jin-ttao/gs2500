사용자 스크린샷에서 카드와 3D가 따로 움직이는 현상을 수정했다. 아래 최초 구현의 '별도 하루 관찰' 설명은 이번 변경으로 대체된다.

- `npm test`: 워크플로·계산·재생 **92/92**, 기존 3D·렌더러 **165/165**, 총 **257/257 통과**. 빌드·문법·diff 검사 통과.

## 실제 데스크톱 브라우저 확인 (2026-09-22)

검사 URL: `http://127.0.0.1:4175/`, Codex 인앱 브라우저, 1280×720.

- 로그인 → 매대 목록 → 4점포 비교 계산 → 삼성역점 B안 → 안내문 편집·승인 → 점주 부분 실행 회신 → JPEG 접수 → 매니저 회고를 실제 클릭했다. 도구 왕복 시간을 포함한 소요 시간 **51.907초**. 사람 대상 사용성 연구의 평균 시간은 아니다.
- 승인 전 점주 화면은 제안 없음으로 표시했다. 승인 후 B안과 수정한 안내문만 표시됐고 A/C 후보는 나타나지 않았다.
- JPEG 선택 후 실제 미리보기와 `사진 접수됨`을 확인했다. Markdown 파일을 선택하면 이미지 형식 오류가 나오고 이전 사진이 유지됐다.
- 부분 실행 후 실행 어려움으로 변경하면 사진이 해제되고 거절 의견이 남았다. 초기화는 로그인 화면으로 돌아간다. 새로고침도 메모리 상태를 초기화한다.
- 회고의 실제 데모 집계는 제안 4/4, 승인 1/4, 회신 1/4, 사진 1건이었다. 별도 4주 합성 사례는 이 집계에 섞이지 않으며 미회신 사례의 관찰값은 0이 아닌 미관찰로 표시했다.
- 4점포 × 현재안/후보 3개, 총 16개의 3D 뷰포트가 렌더링됐다. 카드별 시각·매장 내 인원·결제가 진행했고 일시정지 버튼도 동작했다. 최신 정상 빌드의 콘솔 오류는 관찰되지 않았다.
- 3D 모듈에 의도적으로 HTTP 503을 반환하는 로컬 QA 프록시(4176)에서도 연결 실패 안내, 30일 계산 유지, 후보 승인, 점주 전달, 초기화가 동작했다. QA 프록시는 검사 후 종료한다.
- 브라우저가 첫 프레임에서 음수 시간 간격을 줄 수 있는 오류를 수정하고 회귀 테스트를 추가했다. 연속 사진 선택·초기화 중 디코딩 완료 시점의 경합도 방어한다.

## 빌드·서버 검사

- 최종 `npm test`: 워크플로·계산·컨트롤러 **81/81**, 기존 3D **159/159**, 총 **240/240 통과**. 컨트롤러 9개 검사는 실제 `app.js` 이벤트 핸들러를 모의 DOM에서 실행하며 브라우저 렌더링 검사와 구분한다.
- `npm run build`, `npm run check`, `git diff --check` 통과.
- 최초 구현 커밋 `a5078f7`에서는 기존 `demo/` 소스 변경이 없었다. 최신 변경은 렌더러의 선택적 embedded 모드와 관련 테스트만 추가하며 구매 판단 엔진은 변경하지 않았다.
- 루트·기존 3D·워크플로 런타임 경로는 HTTP 200. 환경 파일, 서버 파일, 테스트 파일, 경로 탈출, 미지원 API는 404.
- 빌드 산출물에서 환경/서버/세션 파일 및 비밀키 패턴 미검출. 서버는 127.0.0.1에만 바인딩한다.
- `scripts/browser-e2e.spec.mjs`는 별도 실행용 브라우저 테스트 명세다. Playwright 러너로 실행했다고 주장하지 않는다. 위 UI 검사는 실제 인앱 브라우저 조작 결과다.
