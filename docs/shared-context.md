# GS2500 팀 공통 맥락

2026-09-21 기준의 구현 공유 문서입니다. [3분 콘티 HTML](../design/reference/gs2500-storyboard-handoff.html)은 화면과 발표 동선의 참고 자료입니다. 실제 동작과 데이터 계약은 통합한 코드 및 검증 결과에 맞춥니다.

## 문제와 목표

영업관리 매니저는 여러 가맹점의 전년 동기 대비 매출 실적을 보고 어디를 먼저 도울지 판단합니다. 본사 표준 진열은 후보를 만드는 참고 지침일 뿐, 점포마다 다른 취급 상품·재고·동선에 그대로 적용할 답은 아닙니다. 진열 변경 역시 매출 개선 수단 중 하나입니다. 목표는 점주가 납득할 수 있는 작은 실행을 제안하고, 본사가 여러 점포의 성과와 실행 부담을 함께 보며 다음 지원을 결정하는 루프입니다.

매니저의 핵심 경험은 성과 분석, 시뮬레이션 과정·결과, 진열 제안 세 가지입니다. 점주는 승인된 자기 점포 제안만 보고 수용·부분 실행·거절을 선택합니다. 실제 변경은 매장에서 하고, PC 데모에서는 사진 파일과 선택적 의견을 접수합니다.

## 3분 데모의 연결 경로

1. 매니저 홈에서 담당 점포의 전년 동기 대비 매출을 확인하고 개입할 매대를 고릅니다.
2. 매대별 현재 진열, 재고, 판매 근거를 보고 여러 진열 후보를 확인합니다.
3. 여러 점포의 여러 후보를 전광판처럼 함께 봅니다. 각 점포의 현재 진열을 기준선으로 놓고 후보들을 동일 조건에서 30일 시뮬레이션합니다. 점포 수와 후보 수를 고정된 제품 제한으로 취급하지 않습니다.
4. 매니저가 후보의 예상 효과, 신규 발주 필요 여부, 점주 작업 부담과 가정을 보고 승인합니다. 점주 안내 문자 초안은 수정 가능하지만 실제 발송은 하지 않습니다.
5. 점주는 현재 매대 사진 한 장의 위치 표시와 선반 단면도, 추천 이유를 보고 무엇을 어디로 옮길지 이해합니다. 변경 후 사진을 미리 만들어 보여주지 않습니다. 실행 후 올린 사진은 접수만 하며 자동 판독·검증했다고 주장하지 않습니다.
6. 4주 후 합성 사례에서 승인·회신·미실행의 분모와 좋은·부진 사례를 함께 보고, 매니저와 본사가 다음 지원이나 지침 수정을 판단합니다.

## 팀 작업 경계와 데이터 정합성

- 유찬님은 `codex/multi-store-live-3d` 브랜치에서 3D 시뮬레이션 전광판과 후보 상세를 담당합니다. 기존 기능과 테스트를 보존하며 통합하고, 콘티의 3D 와이어프레임을 새로 그리라는 지시로 해석하지 않습니다.
- 타오는 3D 밖의 매니저·점주 웹앱, 승인과 회고 흐름, 공개 Vercel 배포와 전체 E2E를 담당합니다. 메인 `/goal` 작업이 이 통합의 허브입니다.
- 점포·매대·상품·재고·현재 진열·후보·예측 결과는 UI별 임의 숫자가 아닌 재현 가능한 공통 합성 시나리오로 맞춥니다. 삼성역점 `H-0412`, 매대 `B-03`은 콘티를 따라가는 대표 사례입니다. 후보 ID, 선반 위치, SKU 및 수치는 동료 코드의 실제 입력·출력을 확인한 뒤 캘리브레이션합니다.
- 전년 동기 대비 실적, 현재 진열 대비 30일 시뮬레이션 예상, 합성 4주 후 관찰은 서로 다른 수치와 시점입니다. 시뮬레이션이나 관찰 사례를 검증된 인과적 매출 상승으로 표현하지 않습니다.
- 별도 DB나 외부 저장 서비스는 쓰지 않습니다. 공개 URL에서 데모 경로는 실제 클릭 가능해야 하지만, 같은 브라우저의 데모 상태를 실제 기기 간 전달·영구 저장·문자 발송·발주 실행으로 설명하지 않습니다.

## 통합 시 확인할 것

유찬님 산출물의 실제 실행법과 입력·출력 계약을 먼저 확인합니다. 웹앱에서 점포·매대·후보를 어떻게 지정하고, 기준선 및 30일 결과를 어떤 형태로 받는지 정한 후 공통 fixture 또는 어댑터로 연결합니다. 데스크톱 공개 URL에서 `성과 → 매대 → 전광판 → 후보 → 승인 → 점주 → 사진 접수 → 회고`를 E2E로 확인합니다. 사진 접수와 실행 확인은 구분합니다.

최종 제출 마감은 2026-09-22 12:00 KST입니다. 공개 URL, 공개 GitHub, 누구나 링크로 볼 수 있는 데모 영상, 5페이지 이내 발표 자료가 필요합니다. 실제 실행한 `/goal` 원문과 메인 세션 JSONL도 별도 제출 대상입니다.
