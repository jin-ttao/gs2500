반드시 지킬 것
매대가 기본 단위
점포가 아니라 매대 단위로 제안·시뮬레이션·회고가 돕니다. 코드는 H-0412 · B-03 형식.
전체 실행 CTA는 목록에만
옵션 단위로 돌리는 버튼을 두면 안 됩니다. 목록 상단의 "전체 시뮬레이션 돌리기" 하나로 돌릴 수 있는 모든 매대·모든 옵션을 병렬 실행합니다.
옵션 클릭 = 타겟 강조
옵션 카드를 누르면 매대 사진에서 해당 칸만 빨간 박스로 강조합니다. 좌표는 사진 기준 퍼센트로 저장하고, 사진이 바뀌면 좌표도 다시 지정합니다.
예상치와 관찰치를 섞지 않기
30일 시뮬레이션 예상치(+3.9%)와 4주 관찰 달성률(95.2% → 101.6%)은 라벨·색·단위를 다르게 둡니다. 같은 축의 그래프에 올리지 않습니다.
분모 고정
회고 퍼널의 % 분모는 항상 제안한 매대 수로 고정합니다(4 / 3 / 2). 단계마다 분모를 바꾸면 채택률이 부풀려집니다.
사진은 접수만
점주가 올린 사진은 첨부로만 저장합니다. 진열이 바뀌었는지 자동 판독하는 기능은 만들지 않고, 화면에도 그렇게 적습니다.
화면 전환 경로
로그인(00) → 홈 실적(01) → 진열 시뮬레이션 탭 = 매대 목록(01B) → 행 열기 = 매대 상세(02) → 전체 시뮬레이션 돌리기 → 전광판(03) → 옵션 상세·선택(04) → 역할 전환 = 점주 화면(05) → 역할 전환 복귀 = 4주 회고(06).
이 경로만 클릭이 통하면 됩니다. 목록의 나머지 세 행, 필터 칩, "제외 기준 보기", "다음 제안" 등은 눌러도 되지만 화면이 없어도 무방합니다. 발표에서 누르지 않습니다.
뒤로 가기는 브라우저 기본 동작으로 충분합니다. 별도 히스토리 관리는 하지 않습니다.

목표 미달·하락은 빨강, 달성·상승과 시스템 액센트는 파랑. 그 외 색은 쓰지 않습니다. 장식용 그라디언트 배경도 쓰지 않습니다.
숫자는 모노스페이스
퍼센트·금액·코드·시각은 IBM Plex Mono, 문장은 IBM Plex Sans KR. 금액 단위는 천원으로 통일합니다.
소제목만 읽어도 이해되게
"주변 특수" 같은 명사 라벨 대신 "2주 뒤 코엑스 박람회, 작년 이 주에 18% 더 팔렸습니다"처럼 문장으로 씁니다. 설명은 아래 한 줄.
AS-IS는 취소선, TO-BE는 강조
제안 제목은 배지(점포) + 매대명 + AS-IS → TO-BE 구조를 유지합니다. 문장형 질문 제목으로 바꾸지 않습니다.
말하면 안 되는 표현
"매출이 3.9% 오릅니다"가 아니라 "30일 시뮬레이션에서 현재 진열 대비 3.9% 높게 나왔습니다". 확정·인과 표현을 화면 문구에 쓰지 않습니다.
"AI가 원인을 찾았습니다"가 아니라 "남은 가설"·"확인할 후보". 발주와 행사 가설을 먼저 제외했다는 순서를 지웁니다.
점주에게 지시하는 말투를 쓰지 않습니다. "옮겨 주세요", "어려우시면 알려주세요" 수준으로 씁니다.
부진 점포를 평가하는 문구를 넣지 않습니다. 회고 화면의 목적은 다음 지원을 고르는 것입니다.
